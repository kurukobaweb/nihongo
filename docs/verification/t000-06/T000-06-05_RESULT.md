## production共通technical margin

T000-06-05の規則に従う。

```text
overrun_basis
= max(0, 全対象環境の最大total_overrun_seconds)
= 0.02300000000000324

method_difference_basis
= 全対象環境の最大duration_method_difference_seconds
= 0.060274000000007

combined_basis
= max(overrun_basis, method_difference_basis)
= 0.060274000000007

production common technical margin
= combined_basisを下回らないよう0.01秒単位で切り上げ
= 0.07秒
```

全MVP対象環境の根拠値が`0.07秒`以内であるため、ユーザー承認によりproduction共通technical marginは`0.07秒`を維持する。

判定式は次とする。

```text
D <= P + 0.07
```

境界一致は上限内とし、判定前にdurationを0.01秒へ丸めない。

## MVP対応対象

ユーザー承認により、今回の4環境をMVP対応対象とする。

- env-a
- env-b
- env-c
- env-d

SafariではWebMの`format.duration`が`N/A`となる場合があるため、env-d正式計測runtimeではPR #66の互換fallbackを適用した。既存の数値`format.duration`を優先し、それを取得できない場合だけffprobe packetの`pts_time + duration_time`最大値からWebM durationを算出する。Chrome系の既存duration取得経路は変更していない。

env-dのactual MIME typeは`audio/webm; codecs=opus`で、Chrome系との違いは空白表記のみであり、媒体形式とcodecはいずれもWebM / Opusである。

## 外部入力デバイスに関する既知懸念

Bluetoothイヤフォン、Bluetoothマイク、有線外部マイクは今回の正式集計対象外とする。

AndroidでBluetoothイヤフォンのマイクを使用した切り分けtrialでは、内蔵マイク時より大きい`duration_method_difference_seconds`が観測された。正式結果はAndroid内蔵マイクで取り直し、Bluetooth入力trialはproduction共通technical marginの根拠値へ含めていない。

このため、外部入力デバイスについては次の扱いとする。

- 今回の`0.07秒`の根拠値には含めない
- 今回のMVP正式検証条件としての適用保証対象外とする
- 既知の重要懸念として記録する
- 将来、外部入力デバイスを正式サポートする場合は入力経路別の追加検証を行い、marginまたはduration判定方法を再評価する

現時点では外部入力デバイス利用そのものをMVP非対応機能としてUIで禁止する決定までは行わない。
