# modernspeech / azure-speech

日本語スピーチ練習アプリの MVP 設計・開発用リポジトリです。  
本プロジェクトは、以下の 3 段階で進めます。

1. **MVP の作成とテスト環境の検証**
2. **検証結果をもとにした本番環境の構築**
3. **本番環境構築後の運営**

このうち、**現時点で詳細設計の対象として扱うのは ①「MVP の作成とテスト環境の検証」まで**です。  
②および③はプロジェクト全体の到達点として README 上に位置づけますが、詳細な設計・運用手順は、①の検証結果を踏まえて段階的に具体化します。

---

## 1. このリポジトリの位置づけ

このリポジトリは、MVP の前提条件・設計判断・未確定事項を管理するための設計リポジトリです。  
現在は **設計文書フェーズ**であり、実装コードは未着手です。

本リポジトリの役割は次のとおりです。

- MVP の前提条件を明文化する
- 実装前にシステム構成・責務分離・データ設計を整理する
- 未確定事項を本文から分離し、追跡可能な状態で管理する
- MVP 検証後に、本番構築・運営へ引き継げる文書基盤を整備する

## 2. プロジェクトの進め方

### 2.1 フェーズ ①: MVP の作成とテスト環境の検証
現在の主対象です。  
このフェーズでは、MVP に必要な機能・設計・データ構造・外部連携・運用前提を整理し、テスト環境で成立性を検証します。

このフェーズで主に扱うもの:

- システムアーキテクチャ
- DB 設計
- Azure AI Speech 連携前提
- 非同期ジョブ設計
- セキュリティ・認証・ログ設計
- 一時音声ファイルの扱い
- MVP に必要な最小運用手順
- PoC 対象機能の位置づけ整理

### 2.2 フェーズ ②: 検証結果をもとにした本番環境の構築
フェーズ①の結果をもとに、本番環境の構成・運用条件・監視条件・費用前提を再確認し、本番導入のための構築を行います。

現時点では、本フェーズの詳細設計は確定対象に含めません。  
本番環境の具体構成、予算上限、通知チャネル、バックアップ保管先、運用責任分担などは、検証結果を踏まえて後続で具体化します。

### 2.3 フェーズ ③: 本番環境構築後の運営
本番公開後の継続運営フェーズです。  
監視、障害一次対応、バックアップ運用、Secrets 運用、改善サイクル、利用状況の把握などを含みます。

現時点では、将来必要になる運用観点の受け皿だけを文書上に持ち、運営の詳細 Runbook は本番構築確定後に整備します。

## 4. MVP の固定前提

以下は、現時点で確定前提として扱う内容です。

### 4.1 技術スタック
- Laravel
- Inertia.js
- Vue 3
- Tailwind CSS
- Python speech evaluation service
- PostgreSQL 16
- Nginx
- Stripe
- Azure AI Speech

### 4.2 DB・データ前提
- DB は **PostgreSQL 16 / UTF-8**
- `questions.has_model_answer` は採用
- `questions.question_type` は不採用

### 4.3 音声データ前提
- 音声ファイルは **永続保存しない**
- 音声は一時ファイルとして扱い、処理後に削除する
- 退会フローは以下の 4 段階を前提とする

```text
Stripe 解約 → 音声削除 → soft delete → 30日後 hard delete
```

### 4.4 Azure AI Speech 前提
- Region: `japaneast`
- SKU: `Standard (S0)`
- MVP では **STT** を利用
- **Pronunciation Assessment（日本語）** は PoC 対象として扱う

## 7. 未確定事項の扱い

未確定事項は、README や設計本文の本線には混在させず、`docs/OPEN_ISSUES.md` に集約して管理します。  
詳細設計対象がフェーズ①であることを踏まえ、以下のような項目は現時点で確定扱いにしません。

- Azure AI Speech の月額予算上限
- Pronunciation Assessment PoC の Go / No-Go 基準
- Azure API キーローテーション手順
- 障害通知チャネル
- 外部バックアップ保管先・暗号化方式・復旧責任
- 音声残存ファイル削除バッチの実行頻度
- `expected_duration` の根拠
- continuous recognition の安定性評価結果

未確定事項は **1 ID = 1 管理項目** を原則とし、他文書へ全文重複させない方針とします。
